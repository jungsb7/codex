# 54단계 재검증 캐시 복원

채팅 첨부 다운로드 없이 이 보관 브랜치에서 캐시를 받는다. 원래 계산의 gzip 바이트를 9,000,000바이트 이하 조각으로 나눴으며 재계산하거나 수치를 변경하지 않았다. 총 287,113,365바이트, 3개 캐시다. `manifest.json`에 조각과 원본 SHA256을 기록한다.

## 새 PC 세션

현재 작업을 보존하고 `archive/model54-session-20261025`의 최신 파일을 받는다. 이미 작업 중인 폴더에 강제 reset/pull하지 않는다. 별도 새 폴더로 clone하거나 새 세션 에이전트가 fetch 후 이 디렉터리만 안전하게 가져오도록 한다. `main`에는 이 파일들이 없다.

저장소 루트에서 Python 3로 실행한다(Windows에서는 `python3` 대신 `py -3` 가능):

```sh
python3 handoff/pressure-cache-54-transfer/restore.py --destination ../pressure-cache-54
```

조각 및 전체 파일 해시를 검사한다. 동일한 기존 파일은 재사용하고 다른 파일은 덮어쓰지 않는다. 대상 디스크는 원자적 hard link를 지원해야 한다(일반 NTFS/APFS/ext4 가능). 실패하면 기존 파일을 지우지 말고 오류를 확인한다. 복원본은 저장소 밖에 두며 웹 배포에 포함하지 않는다.

- `fine240.bin.gz`, `time120.bin.gz`: 동일한 105년 말 상태에서 106년 240/120단계 비교, 전체 19,990개 웅덩이 중 시간 차이 1m 초과 32개 지점 검증용.
- `closed0.bin.gz`: 지정 통로 교환 비활성 대조.

Node 24.19.0의 `v8.serialize` 자료를 gzip 압축한 캐시다. Node 24에서 gunzip 후 deserialize한다. `pressure-coupling/compare.cjs`, `diagnose.cjs`의 기존 `/workspace/pressure-cache-54` 경로는 **사용자 PC 경로가 아니다**. 새 세션에서 복원 위치를 확인한 뒤 로컬 경로에 맞춰 사용한다. 기존 검증 결과를 덮어쓰지 말고 새 진단 결과는 별도 위치에 저장한다. 캐시가 없다고 `run.cjs`를 재실행하지 않는다.

원본 결과의 시간 최대 수위 차이는 4.226539260807272m, 1m 초과 지점은 32개, 지점·기간 쌍은 156개다. 파일 복원 검증은 과학적 수렴이나 정확성 개선이 아니다. 다른 단계의 캐시, native 실행 파일 및 전체 보조 백업을 포함하지 않는다.
