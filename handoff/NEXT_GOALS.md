# 다음 세션 권장 목표: 계절 지도 경량화와 대표 경관 품질 점검

상태: **제안, 미착수**. 이번 사용자 요청은 인수인계와 목표 제안까지다. 후속19의 세 기능은 구현·배포 완료했다.

현재 사용성을 가장 크게 개선할 지점은 계절 기능의 최초 추가 로딩 약41MB다. 확대 표현도 전 대륙에 공통 적용했으므로, 다음은 입력을 새로 만드는 대신 같은 자료를 더 빠르게 읽고 대표 경관의 화면 품질을 정리하는 한 단계로 제한하는 것이 좋다.

## 1. 계절 자료를 필요한 만큼 읽기

- 기존 기온·강수 Float32와 표시용 로그 양자화 유량을 그대로 유지하며 기간별 파일로 나눈다.
- 개체 정보에 필요한 수계 연결·유역 메타데이터를 계절 유량 배열과 분리한다.
- 선택 기간부터 로드하고 인접 기간을 미리 읽는다. 불러온 기간은 제한된 캐시에 보관한다. 빠르게 기간을 바꿔도 늦은 응답이 최신 선택을 덮어쓰지 않게 한다.
- 실패·재시도·해시 불일치·새로고침·뒤로 가기에서 수치와 화면이 일치하도록 한다.
- 제안 성능 목표: 기존 기본 지도 파일을 제외한 **첫 선택 기간용 추가 전송량10MB 이하**. 기기·망별 절대 속도는 보장하지 않고 동일 환경에서 전후 로딩·메모리·기간 전환 시간을 측정한다.

완료 기준: 전268857격자×12기간 기온·강수와 전45824후보 물길의 기간 표시값이 이전 자료와 동일하고, 기존 전체41MB를 먼저 받지 않아도 선택 기간 지도가 나타난다.

## 2. 대표12경관 품질 점검

자연11권역에서 각각1곳, 기존 호수에서1곳을 골라 이름·좌표·선정 이유를 목록에 고정한다. 산지/계곡, 건조지, 온대림·열대림, 초원, 습지, 한랭권, 해안/섬을 포함하되 각 권역의 실제 후보에 맞춰 선택한다.

- 12배/24배/32배 확대와 데스크톱·390px 모바일을 비교한다.
- 타일 이음새, 과한 등고선·물길 밀도, 숲/습지 가장자리, 원본 격자·기호·지명 충돌을 정리한다.
- 자연물 선택 강조가 표시선과 맞는지, 기존 설정만 보기에서 후보가 숨는지, 좌표/자연물/계절 JSON이 같은 지점을 가리키는지 검사한다.
- 원본 해안·호수 마스크와 미확정 하류 상태를 보존한다. 표시 개선 때문에 지형·식생·수계를 새로 확정하지 않는다.

완료 기준:12곳의 전후 캡처·점검표와 발견 문제의 처리 결과가 있고, 세부 형태가 설계 표현임을 화면에서 알 수 있다.

## 3. 검증·배포·종료

새 후속 단계에 저장소의 nature-deployment-manifest.json, 필요한 원본 입력 해시와 기준 커밋을 기록한다. 전체 과거 소스의 integration/MANIFEST.json이 이 Git 저장소에 있다고 가정하지 않는다. 적절한 자료 검사와 브라우저 회귀검사, 공개 패키지 의존성·상대 경로·해시 검증을 완료한 뒤 기존 저장소 main에 변경 목록만 적용한다. 정확한 커밋의 Pages build/deploy를 확인하고 실제 사이트 접속 가능 여부를 구분해 기록한다.

이 단계는 성능과 표시 품질을 마무리하면 종료한다. 미정 수문 경계1184곳 전체 해소나 개별 산림·습지의 실제 피복 확정은 포함하지 않는다.

2. 특정 유역1곳의 실제 유입·저류·넘침 설정 검토 — 물리 수계 확정이 우선일 때. 전역 일괄 확정으로 확대하지 않는다.

두 선택지는 다음 권장 단계의 필수 잔여 작업이 아니다.
