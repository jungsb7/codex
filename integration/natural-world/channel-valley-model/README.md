# 세부 물길과 계곡 단면 후보

원본 45,824개 물길 전체에 세부 중심선, 내리막 종단, 포물선 계곡 횡단면을 구성했다. 기존 23,022구간의 완료된 물수분 계산은 집수권 링크로 연결한다. [화면](index.html) · [결과](REPORT.md) · [출력 목록](output/manifest.json).

이전 확대 지도는 표시용 보간과 둥근 선이었다. 이번 결과는 경로 좌표와 거리, 원본 기준 고도와 후보 바닥 고도, 계곡 반폭, 단면을 수치로 조회·다운로드할 수 있는 **별도 지형 후보**다. 원본 지형·수계·해양/호수 마스크·경제·구지도·아카이브 및 완료된 100년 물수분 결과는 바꾸지 않는다. `actual:null`, `automaticAdoption:false`를 유지한다.

## 생성한 것과 아직 확정하지 않은 것

원본 물길의 126,727공유 지점과 119,143연결을 유지한다. 지류와 본류는 같은 합류점 고도를 공유한다. 500m 이하 간격으로 경로를 표본화하며, 출구와 모든 원본 격자 중심·경계 통과점은 고정한다. 500m는 계산 간격이며 새 관측 지형의 해상도가 아니다. 원본 약26km 격자보다 더 작은 형태는 아래 가정으로 생성했다.

이 결과는 암석 침식 속도, 침식 기간, 퇴적물 운반을 적분한 지형 진화 시뮬레이션이 아니다. 지리적으로 연속된 고해상도 DEM·침수 래스터도 아니다. 단면의 원본 기준면은 두 원본 고도 사이를 선형 보간한 값이며, 실제 지표의 세부 굴곡을 관측한 값이 아니다.

기존 격자에 합류점 없이 두 대각선이 같은 모서리를 통과하는 **3곳·6구간**이 있다. 새 합류나 입체 교차를 임의로 만들지 않고 원본 연결을 유지하며 해당 구간을 명시한다. 따라서 모든 실제 소하천·침식 계곡이 확정되었다고 표현하지 않는다. 새 가지를 추가하거나 원본보다 더 작은 미등록 지류를 발견한 것도 아니다.

## 형태 가정

- 원본 평균 유량 `Q`(m³/s)를 형태의 척도로 쓴다. 100년 웅덩이 계산에서 개별 구간 유량을 역산하지 않는다.
- 목표 절개 깊이 `min(40, 2 + 2 ln(1 + Q))`m, 계곡 반폭 `min(1200, 60 + 18 sqrt(Q))`m. 이 폭은 물이 흐르는 실제 강폭이 아니다.
- 하류부터 역순으로 바닥을 정한다. `bed(upstream) = max(originalHeight - desiredDepth, bed(downstream))`. 하류 바닥보다 낮아지는 절개는 줄인다. 최소 경사는0이므로 평탄한 구간을 허용한다. 원본 해양·호수 지점은 고도와 마스크를 고정한다. 이번 결과에서는 원본 고도를 올린 지점이 없고 최대 절개는 약22.03m다.
- 각 원본 격자의 중심과 경계 사이에서 격자 좌표 기준 최대8°의 좁은 회랑 안에 `sin³` 형태의 곡선을 둔다. 격자 중심, 경계·모서리 통과점에서 변위가0이다. 이 여덟 방향 회랑은 격자 내부에서 서로 침범하지 않는다. 기존 대각선 교차3곳은 별도다.
- 단면은 `z(offset) = bed + (reference - bed) (offset / halfWidth)²`의 포물선이다. 원본 물 영역의 단면 조회는 `null`이다. 지도에서 계곡 폭을 나타내는 보조 음영도 원본 육지 격자 안으로 자른다. 이것을 새 지형 래스터나 확정된 지리적 계곡 면적으로 사용하지 않는다.
- 단면 적분은 선택 회랑의 형상 진단이다. 단면 면적은 `4/3 × depth × halfWidth`, 길이 방향은 Simpson 단면 적분과 경로 거리로 계산한다. 해양·호수 부분은 제외한다. 이웃 회랑과 합류부의 중복을 통합하지 않았으므로 여러 구간을 더해 전세계 굴착량·퇴적량으로 쓰지 않는다.

후속40 물수분 결과는 원래 웅덩이 지형의 계산이다. 이번 계곡 후보를 그 지형에 반영하거나 수문 계산을 재실행하지 않았다. JSON의 `waterBudget.coupling`은 `reference-only`이며 개별 구간의 새 유량은 `null`이다. 채택하거나 물수분에 결합하려면 연결·저장 지형을 함께 검토해야 한다. 숲 가장자리·습지/미세 침수 경계·실제 강폭·눈 두께·결빙은 이번 결과로 확정하지 않는다.

## 화면과 AI

대표 물길을 선택하거나 원본 물길 번호0–45823을 입력한다. 지도 확대·전체 보기·단면 위치 슬라이더를 쓰며, 지도 클릭으로 가까운 단면을 고를 수 있다. 원본 경로, 후보 경로, 종단, 횡단면을 비교한다. 두 JSON 다운로드는 각각 전체 경로와 선택 단면을 제공한다.

```sh
node integration/natural-world/channel-valley-model/query.cjs 13
node integration/natural-world/channel-valley-model/query.cjs 387 --section 0.5
```

CLI와 화면은 같은 `core.js`를 사용한다. 자료 해시는 읽을 때 검사한다. 브라우저와 Node의 삼각함수 마지막 자릿수는 다를 수 있어 비교 검사는 절대1e-8+상대1e-12 허용치를 쓴다. 다운로드 파일은 그 화면의 수치와 정확히 일치한다. 원본 합류점의 고도와 입력 기록은 정확히 공유한다.

전체 자료는90조각으로 나누고 목록과 선택한 조각만 읽는다. 경로 약794만 표본을 처음부터 전부 내려받지 않는다. 원본 구간ID·상하류 관계·유량·원본 좌표를 각 결과 안에 보존하여 가공된 후보와 구분한다.

```sh
node handoff/restore-inputs.cjs
node integration/natural-world/channel-valley-model/build.cjs
node --test --test-isolation=none integration/natural-world/channel-valley-model/test.cjs
node integration/natural-world/channel-valley-model/browser-check.cjs
```

Node 표준 라이브러리만으로 재생성·AI 조회가 가능하다. 브라우저 검사는 Playwright와 Chromium을 쓴다. 입력·실행 코드 해시는 [요약](output/summary.json)에 고정했다. 새 고해상도 원본 입력을 수집한 작업은 아니다.
