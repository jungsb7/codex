# 원본 지형·여러 출구를 쓰는 물수지 후보

후속37은 문턱 위5m의 가상 수직 기둥 대신 **원본 격자 높이에 따라 넓어지는 저장 영역**과 **같은 하류로 나가는 여러 출구 면**을 사용한다. 다른 집수권/호수/다른 해양 지점과 접촉하면 연결망 전체를 멈춘다. 원본 지형·수계를 수정하거나 세계 설정을 자동 채택하지 않는다. [화면](index.html) · [결과](REPORT.md).

946경계·117,320원본 격자의 유입 배정을 한 번에 준비했다. 4,186개의 추가 원본 지형 기둥을 찾았으며 원본 격자를 새로 합성하지 않았다.57경계 계산에는210기둥이 추가된다. 전체2만구간의 기후 물수지까지 계산했다는 뜻은 아니다.

준비된946곳 중9곳은 기준 문턱보다 낮은 출구가 있어 별도 웅덩이 배수 계산이 필요하다. D567047은 기준 문턱 이하에서 다른 집수권과 연결된다. 이10곳을 현재 엔진에 자동 투입하지 않는다. 지형 준비와 엔진 호환성도 별도다.

## 지형 영역과 출구

`geometry.cjs`는 원본1536×768 격자의 D8 이웃을 사용한다. 경도는 이어지고 위도는 양끝에서 끊는다. 각 경계의 원본 낮은 지점에서 시작해 경로의 최대 높이가 가장 낮은 순서로 확장한다. 어떤 격자가 연결되기 위한 최소 수위를 계산하는 minimax 탐색이다.

- 같은 원본 하류 종착점으로 연결되는 외곽 면은 **출구 후보**로 모은다. 하류의 격자를 상류 저장 공간에 합치지 않는다.
- 다른 종착 집수권·호수·다른 해양 지점과의 첫 접촉은 적용 상한이다. 접촉까지의 경로와 두 격자를 저장한다. 새 경로로 물을 자동 전달하지 않는다.
- 다른 접촉이5m 이내에서 발견되지 않으면 단지 `search-ceiling`이다. 영구 폐쇄/안전 수위라는 뜻이 아니다.
- 첫 접촉 수위 미만의 원본 격자만 저장 영역에 넣는다. 같은 원본집수권 소유권을 확인해 다른 경계와 중복 저장/강수 집계를 막는다.
- 처음 한 개의 선택 출구 면만 제외하는 진단을 했을 때에는 같은 하류의 옆 출구도 중단으로 잡혔다. 최종 모델은 같은 하류의 출구 면을 함께 처리하므로 그 인위적인 조기 중단을 제거했다. 초기 진단을 최종 결과로 사용하지 않는다.

946곳에서5,274개 출구 면을 준비한다. 출구 면은 원본 격자 사이의 위상적 연결이며 실제 강폭/수리 단면 측정치가 아니다. 원본이 거친 격자이므로 세밀한 침수 경계·숲/습지 외곽·소하천 침식 경로를 확정하지 않는다.

## 시간 계산

후속36의 유한 토양200mm·대수층1000mm·침투1200mm/년·토양 배수0.25년·지하수 복귀2년·수면 증발0.5m/년을 그대로 별도 설계 가정으로 사용한다. 침투1/4, 복귀 시간4배의 조건도 비교한다. [후속36 가정](../finite-water-model/README.md)을 참고한다. 눈/융설/증발산의 기존 기온식, 하상 침투/외부 지하수 손실0가정, 빙설 열수지 공백은 유지한다.

새 지형 기둥에 원본 웅덩이·안장 분할을 다시 만들고,117,320격자를 원본 receiver 경로에서 처음 만나는 새 기둥에 배정한다. 새로 잠긴 격자는 강수/융설을 수면으로 보내며 같은 육지 유출을 중복 가산하지 않는다. 현재946모델의 내부 안장은 모두 기준 문턱 이하임을 확인했다. 이 조건에서 출구 인출은 아직 분리된 높은 웅덩이를 임의로 빼지 않는다.

총 설계 폭 `W=max(10,4Qref/C)`는 유지하고 같은 하류 출구 N면에 `W/N`씩 나눈다. 면이 늘었다고 전체 폭을 N배 늘리지 않는다. 각 면의 원본 연결 문턱 `zc,i`와 수신 격자가 속한 하류 웅덩이의 이전 단계 수위 `zd,i`를 사용한다:

`Qi = C (W/N) max(max(zu-zc,i,0)^1.5 - max(zd,i-zc,i,0)^1.5,0)`

실측 보정된 잠긴 월류 공식이 아닌 단방향 설계 함수다. 하류 수위의 억제는 지원하지만 일반 역류·하도 손실·실제 이동 시간은 지원하지 않는다. 총 폭은 실제 강폭 추정이 아니다.

지형이 넓어지는 구간에서 면적이 달라지는 전체 원본 기둥 곡선을 사용해 `Vnew + dt ΣQi(Vnew) = 사용 가능한 물`을 푼다. 선택한 상한 아래 해가 없으면 상한까지의 물과 방류를 장부에 남기고 나머지는 `unresolvedM3`로 보존한다. 방류는 각 출구의 양의 유량 비율로 나누며, 같은 원본 하류 집수권의 실제 해당 격자 배정으로 한 번씩 보낸다. 바다행은 기존 해양 종착점에 합산한다.

하류에 전달 중인 물은 수신 경계의 `transitM3`에 담고 다음 소단계에 공급한다. 이는 수치 지연이며 실제 이동 시간을 정한 것이 아니다. 내부 송수신은 외부 유입에 더하지 않는다.

## 중단과 검증 범위

하나라도 지형 상한을 넘는 소단계가 나오면 **57경계 전체**를 같은 단계에서 멈춘다. 이후 강수·유입을 만들지 않고, 뒤의 연도도 저장하지 않는다. 마지막 단계는 접촉을 지나친 초과 물량까지 보존하는 진단 장부다. 적용 범위 안에서 받아들이는 시간은 `lastAcceptedTimeYears`, 접촉 발생의 수치 구간은 `stop.lowerTimeYears`~`upperTimeYears`다. 상한 도달을 물리적으로 정확한 사건 시각이라고 주장하지 않는다.

기준은3년차3위상, D221625→D200167 접촉으로 중단한다. 저침투 조건은1년차2위상 D258447→D243078 접촉으로 중단한다. 기존100년 결과와 같은 기간의 물량 비교로 오해하지 않도록 화면/AI에 중단 기간을 붙인다. 전역100년 혼합망 대체 물수지는 계산하지 않는다.

60·120단계/위상에서 기준 후보의 첫 접촉 지점과 상한 시각이 일치했다. 두 민감도 조건은 별도 간격 검증을 하지 않았다. 마지막 단계의 초과 물량은 간격에 따라 달라지며 확정된 실제 넘침량이 아니다.

공개 원본 payload만으로 재현하며 새 아카이브/원본 계측을 업로드할 필요가 없다. 동적 계산은 기존 `basin-water-budget/source.cjs`의10.2MB를 그대로 읽는다. source의 각 조각/전체 해시는 이전 로더가 확인한다.

화면·JSON 다운로드·AI는 동일한 `view.js.query`를 쓴다.946경계 모두 조회할 수 있지만 `computed:false`이면 `annual`, `localTotals`, `localFinal`은null이다. `componentTotals`/`stop`은57경계 공통 결과이며 다른889경계의 물수지가 아니다. `annual.complete:false`는 선택 연도의 부분 기간이다. 중단 뒤100년 조회를 거부하고 오래된 결과를 숨긴다. `actual:null`, `automaticAdoption:false`를 유지한다.

`output/models.json.gz`에는 일괄 지형/배정, `domains.json`에는 출구/접촉/호환성/전체 분류, `review.json.gz`에는 화면/AI 결과가 있다. 원본 입력과 새 코드 해시는 provenance에 기록한다. 지도 그림은 연결 가능한 영역이며 현재 실제 침수면이 아니다.

기존108보류·14중단, 종료9곳/D193196/D126467/D147845/D144758 내부 검토는 재개하지 않았다. 원본 세계·경제·기후·수계·마스크·구지도·고정 보관 브랜치는 보존한다.

AI의 `outletTransfers`는 경계의 각 출구 면별 설계 폭과 중단까지 누적 전달량이다. 합계는 지역 `releasedM3`와 같고 전체 설계 폭도 보존한다. 지형만 준비한 경계에서는null이다.
