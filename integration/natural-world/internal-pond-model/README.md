# 웅덩이 내부 연결과 연속 지형 저장 — 후속50

네 경우의 계산,자료22검사,브라우저42검사를 완료했다. 배포 상태는 [배포 기록](validation/deployment.json)을 확인한다. 공간·시간 수렴 한계는 [결과](REPORT.md)에 명시한다.

기준main은 `c32a3c50c0b63e8f2310af5732d882645ebcc9e7`이다. 후속49의 공간8/16 비교에서 기간 말 수위가1m 넘게 달라진365개 웅덩이를 대상으로 한다. 그 안의17,123개 원본 격자를 별도 내부 저류칸으로 나눈다. 전체3232개 웅덩이 중 나머지는 기존 단일 수면 단위를 유지한다. 원본 외부 연결9858개는 실제 from/to 격자에 연결하며, 원본 호수 출구는 그대로 둔다.

## 지형과 저장

후속47의 공유 모서리 높이와 결정론적 내부 기복을 연속 함수로 재구성한다. 4×4 잡음 패치마다 Gauss 적분으로 원본 평균 고도를 맞춘다. 이 보정은 분할 수에 독립적이다. 원본 격자의 구면 면적을 같은 면적 가중치로 나눈다. 각 삼각면 안에 정확한6차 적분 평균을 맞추는 중심점을 넣고3면으로 나누어 원본 격자 면적과 평균 높이를 보존한다. 16/32분할은 각각1536/6144개 선형 삼각면이다.

잠긴 삼각면의 부피는 수위의 구간별3차식, 잠긴 면적은 그 도함수다. `poly.h`는 높이 절점마다 계수를 만든다.32절점마다 독립 삼각면 적분으로 누적 오차를 재설정한다. 바닥의 계수는 정확한 시작 조건을 사용한다. 급경사 출구에서1e-8m³ 이하도 유효 수두를 만들 수 있으므로 역함수는 큰 절대 부피 허용오차로 이를 마른 바닥으로 바꾸지 않는다.

각 원본 내부 칸은 여전히 하나의 수위를 갖는다. 삼각면은 칸 안의 부피와 잠긴 면적 계산용이며, 칸 내부의 장애물 연결이나2차원 운동량을 따로 풀지 않는다. 연결용 지형 채움은 실제 저장 지형으로 사용하지 않는다.

## 내부 연결과 물수지

같은 원래 웅덩이에 속한8방향 이웃 칸을 연결한다. 문턱은 공유 변/꼭짓점의 최소 높이이며, 대각선 연결도 가정한 유한 폭 통로다. 유효 폭과 월류 계수는 기존 시나리오의 규칙을 사용한다. 원본 소유권을 가로지르는 새 내부 연결은 없다.

양방향 월류식은 기존 `C W ([h_a-z_c]_+^1.5 - [h_b-z_c]_+^1.5)`를 유지한다. 미소 저장량의 비음수와 보존을 위해 두 칸씩 제한된 암시적 교환을 풀고, 정순/역순 반 시간 간격으로 전체 연결을 순회한다. 작은 값의 유효 자릿수를 보존하기 위해 이동량 또는 남은 물 중 작은 쪽의 제곱근을 미지수로 푼다. 모든 교환에서 잔차를 검사하고 수렴하지 않으면 중단한다. 허용오차는 상대 부피 오차와 수위의 float64 표현 간격에 따른 월류량 오차를 함께 기록한다. 전역 동시 방정식과 같은 해법이라고 부르지 않는다. 연산 분할에 따른 시간 오차는120/240 비교에 포함된다. 교환은 출발 칸의 물보다 많이 내보내지 않으며 같은 양을 수신 칸에 더한다. 해양은0m의 지정 수두 경계다. 새 연속 곡선 입력이 없을 때는 기존 엔진 경로를 유지한다.

초기 상태는 후속40 기준100년 끝과 같다. 선택된 웅덩이의 초기 물을 한 공통 수위에서 내부 칸별로 나눈 뒤 합계의 부동소수점 잔차만 가장 많은 칸에 돌려준다. 공간 분할을 바꾸면 이 내부 분배는 달라질 수 있지만 원래 웅덩이와 집수권 총량은 같다.120/240 시간 비교의 내부 칸별 초기 물은 정확히 같다. 이는 과거 내부 흐름을 재계산한 초기 상태가 아니다. 대상 육지의 눈/토양/지하수/이동 저장은 그대로 유지한다.

선택된102개 배경 웅덩이의11,186격자는 보관된 원본 localDischarge에서 기간별 유입을 복원한다. 집수권 총량을 면적에 따라 임의 배분하지 않는다. 입력 gzip에는 선택된 격자의 유입만 담으며 원본 파일과 원본 유량의 해시를 기록한다. 모든 배경 유입과 대상 육지 강수는 각각 한 번만 들어간다.

강수는 후속49의 가정된512지역 사건 곡선(80%를48시간 강수3회,20%균등)과 같다. 같은 해의 강수 총량과 기온/PET/배경·호수 입력은 유지한다. 내부 칸 사이 이동은 원래 집수권 물수지에서 상쇄된다. 공개 정방향/역방향 누적량은 전체 수문 시간단계의 순교환을 방향별로 누적한 값이다. 같은 단계 안의 두 순회에서 반대로 이동한 양은 상쇄되므로 이를 반 단계의 총 통과량이라고 부르지 않는다. 수위 이력과 극값은 단계 끝(극값은 기간 시작 포함) 기준이다.

단일 수면 대조의 수위는 웅덩이 전체의 공통 높이다. 선택 칸의 바닥 아래일 수도 있으며, 그 칸의 실제 침수 수위가 아니다. 내부 칸의 수위와 대조 공통 높이의 차이를 관측 홍수 높이 변화로 해석하지 않는다.

## 재현

Node24와 C++17, Node API 헤더가 필요하다. 큰 중간 캐시는 저장소 밖에 둔다.32분할 곡선 은행은 약2.15GB이며 공개 결과에 중복해서 넣지 않는다.

```sh
node integration/natural-world/internal-pond-model/compile.cjs /tmp/node-v24.19.0/include/node
node integration/natural-world/internal-pond-model/prepare.cjs 16 32
node integration/natural-world/internal-pond-model/run.cjs
node integration/natural-world/internal-pond-model/control.cjs
node integration/natural-world/internal-pond-model/build.cjs
node integration/natural-world/internal-pond-model/pack.cjs
node --test --test-isolation=none integration/natural-world/internal-pond-model/test-*.cjs
```

전체 실행은 `run.cjs`가 하나씩 처리한다.16GiB 환경에서 두 전체 계산을 동시에 시작하지 않는다. 시작 전 메모리 여유만으로 실행 중 최대 사용량을 보장할 수 없다.

`INTERNAL_POND_CACHE` 기본값은 `/workspace/internal-pond-cache-50`, `INTERNAL_POND_NATIVE` 기본값은 `/tmp/internal-pond-model.node`다. 기준 후속48/49 입력 복원과 컴파일 방법은 해당 단계 README를 따른다. 오래된 빌드/패키징 스크립트를 실행하지 않는다. `collect-background.cjs`는 필요할 때만 아카이브의 `stage3/inputs/hydrology.json`을 명시해 실행한다. 이미 공개한 선택 유입 자료만으로 후속 계산은 재현 가능하다.

지점·이력·물수지·연결·침수 GeoJSON은 `query.cjs cell|trace|budget|exchange|geojson ID PERIOD`로 조회한다. 브라우저와 같은 `core.js`를 사용한다. 이력은 float64 비트를 행별 XOR 차분하고 바이트 자리별로 모은 뒤gzip하여 무손실 저장한다. 이전 결과 파일은 덮어쓰지 않는다. 다음 결합 단계가 이어 쓸 수 있도록101년 말 대상 육지의 눈/토양/지하수/이동 저장과 모든 내부 칸의 수면 재고도 `final-state.json.gz`에 함께 보존한다.

전체 남은 구현의 유한한 기준과 순서는 [완료 기준](../../../handoff/MODEL_COMPLETION_CRITERIA.md)을 따른다. 원본/채택판·기존 모드·Oracle은 이번 작업에서 변경하지 않는다.

GitHub 연결 도구의 요청 본문 16MiB 제한에 맞춰 큰 gzip 파일은 9,000,000바이트 이하 조각으로 나눈다. manifest.parts 순서로 합치고 각 조각과 원래 gzip의 길이/SHA-256을 모두 검사한 뒤 해제한다. 이는 수치·압축 바이트를 바꾸지 않는 포장 변경이며 저장소 용량 제한이나 해상도 축소가 아니다.
